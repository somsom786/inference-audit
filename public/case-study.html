01

Where does a request spend its time?

More serving slots let the model work on more sequences at once. We expected shorter waits and better utilization. The request lifecycle explains why a faster start can still lead to a slower finish.

Request lifecycle · schematic, no measured durations
Request arrivesFirst tokenFinish

Wait for a serving slot

A slot can hold an active sequence. When all slots are occupied, another request may wait before the model starts processing it.

Process the input

The model reads the prompt and fills its KV cache with attention state it can reuse during generation. Queueing, prompt processing and delivery all contribute to time to first token.

Generate the answer

The model emits tokens in sequence. Completion latency includes the whole request. A correct on-time answer also has to pass its task check and deadline.

02

Chat bursts made a strong case for four slots.

On homogeneous Qwen chat bursts, four slots raised pooled output throughput. We compared each profile with the same workload manifest and a fixed total f16 KV allocation.

P2-CHAT evidence ↗
03

The result changed with mixed traffic.

Fresh chat, coding, retrieval and dependent agent tasks exposed the trade-off. Four slots improved first-token latency at the highest tested load. Two slots finished sooner and delivered more correct answers within their deadlines.

Neither profile reached the 95% target in every family at any tested load. Chat and agent tasks missed at the highest load.

Why the first baseline overstated the gain

The original control disabled Flash Attention. In the follow-up, the engine's automatic setting enabled it and matched the tuned cold-prefill result within the observed ranges. Default baseline

What interrupted the endurance study?

Windows suspended during Qwen's A2 arm. That arm was excluded and rerun. The retained 180 minutes came from separate segments. Endurance evidence

What can this establish about cost?

The measured trade-offs describe one GPU under synthetic traffic. Fleet savings depend on utilization, redundancy, service targets and billing. Read the technical limitations
