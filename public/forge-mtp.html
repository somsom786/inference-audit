RTX 4070 experiment

One draft token. A faster code stream.

Native multi-token prediction proposes a token ahead of the main model. For Forge Qwen3.5-9B, checking one proposal at a time made code decode faster. Asking for four made it slower.

Same weights. Three clean launches.

Default → one-token MTP → default on Forge Qwen3.5-9B Q4_K_M, RTX 4070 and Ollama 0.40.16. Each arm measured eight code and eight novel-prose prompts, 128 output tokens per request, one stream and an 8,192-token context. The faster of the two controls is the comparison.

Code decode rose from 71.56–71.57 to 76.60 tok/s (+7.0%). Median code completion fell from 1.858–1.865 s to 1.748 s. An earlier matched bracket reached +6.9%. All eight visible code outputs matched both controls in each one-token bracket. Both near-full retrieval checks passed in the fresh bracket.

Prose throughput was roughly flat. Four draft tokens reduced the code median to 55.91 tok/s against controls at 71.55–71.66. Peak board memory in the fresh one-token arm was 8,935 MiB against 8,475–8,499 MiB. This is a single-stream result on a fixed prompt panel. Multi-user capacity and actual savings remain unmeasured.
