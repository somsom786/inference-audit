Know what your inference server can actually handle.

Inference Audit measures how much correct work an LLM server delivers on time. Run bounded workloads against an authorized endpoint and share an audit another engineer can check.

Read the case study View a measured audit

More tokens can mean less useful work.

On repeated chat bursts, four serving slots raised output throughput from 143.77 to 226.70 tokens/s. With fresh chat, code, retrieval and agent traffic, first tokens arrived sooner while fewer transactions finished correctly and on time.

The trials held the total KV allocation fixed. Four slots divided it into smaller context windows, which changes what the server can accept per request.

From workload to shareable audit

  1. Scope the test

    Record an authorized OpenAI-compatible endpoint and the approved traffic budget. Choose synthetic workload families and service objectives.

  2. Measure service

    Track first-token and completion latency, usage-based throughput, task checks and failures. Capture NVIDIA board telemetry when available.

  3. Replay the evidence

    Regenerate HTML, JSON and Markdown from saved observations. Compare performance per workload and document the conditions behind each result.

Benchmark traffic still uses server capacity. Controlled process management is experimental and native CUDA shutdown remains unverified.
