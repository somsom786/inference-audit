# Decisions

- Keep Phase 1–3 evidence and the Phase 4 replication intact. The Phase 4 request contract was 3,800 tokens and the two/four-slot comparison did not preserve the two-slot profile's full per-slot context.
- Keep the existing module boundaries. Runtime uses HTTPX, its pinned HTTP core and PyYAML. Scheduling, storage and reports use the standard library.
- Treat transport, accounting, cache proof and task correctness as separate outcomes. Withhold stage output rates when complete usage coverage is absent.
- Require explicit load authorization. Pin remote HTTPS to a validated public address and verify the original TLS name. Private deployments should use an approved loopback runner.
- Evaluate each workload family and report the lowest supported interpretation of tested capacity. An owned ABBA arm is comparable only when workload contracts match. Independent launches determine the comparison.
- Preserve current and historical evidence separately. SHA-256 seals detect local changes. A stage-boundary resume creates a new attempt with no implicit time or event merge.
- Keep the customer pilot read-only, synthetic, and reversible at the client. Preserve measured performance separately from conditional planning estimates.
