# Inference Audit 0.2.0 engineering audit

## Baseline

Inspected all package modules, configuration examples, CLI, test harness and existing evidence. The 0.1.0 suite passed 20 tests. Package mypy and dependency checks passed. Repository-wide Ruff found five issues in the historical reproduction scripts. Windows NVIDIA telemetry identified an RTX 4070 with 12,282 MiB and driver 621.24. The previous Phase 4 replication remains a segmented, workload-specific finding with a negative strict-capacity result.

| Severity | Location | Defect and impact | Required correction and verification |
| --- | --- | --- | --- |
| High | config / targets | An exact HTTPS origin approval still lets the OS resolve arbitrary A/AAAA answers, including metadata/private destinations. Resolving again at connection time would permit a DNS change. | Validate all remote addresses, connect to one validated address without a second hostname lookup and retain original TLS name verification. Exercise private/mixed DNS, destination pinning and redirects. |
| High | evidence / reporting / legacy | Evidence reads follow symlinks and have no byte or row cap. Report files are opened for overwrite and follow symlinks. Imported Markdown can interpret attacker-controlled formatting. | Bound reads, refuse evidence and destination links, stage atomic writes and keep untrusted display data inert. Test links, malformed and oversized bundles and active report payloads. |
| High | runner / config | Request bounds do not cover evidence storage. A very large generated manifest or partial run can use unbounded practical disk space. Internal monitor/write errors can leave a misleading checkpoint. | Add an evidence budget and free-space preflight, explicit stop reasons, bounded checkpoint and pending-event preservation. Test forced interruption and budget rejection before inference. |
| High | evidence / analysis | Rehashed malformed evidence can mark missing stage rows complete, accept contradictory success fields and allow invalid numbers. The analyzer trusts completion and timing fields that verification barely checks. | Validate semantic stage/row invariants with version-aware checks and keep checksum claims distinct from authenticity. Replay historical evidence offline and test resealed invalid bundles. |
| High | targets / runner / analysis | Missing usage turns an otherwise completed response into an HTTP-equivalent failure. Partially accounted cohorts yield an understated numerical token rate. Warm probes include unverified hits, and tool-call TTFT is conflated with visible content. | Track transport, token and cache evidence separately. Withhold partial rates and unverified cache probes. Save explicit timestamp and event types. Test the fake server under malformed and partial streams. |
| Medium | runner / analysis / controlled | Strict capacity can be declared without showing achieved arrivals, overlap or context evidence. Controlled tail gating uses aggregate p95 only. Wilson intervals assume IID requests, and one launch cannot establish repeatability. | Identify tested passing load and empirical service limits, enforce matched ABBA and per-family gates, report descriptive uncertainty and defer causal claims. |
| Medium | targets / cli | Inspection conflates status with capability. HTTP errors lack conservative overload/context categories. Untrusted text can appear in model listing output. | Keep probing GET-only, classify known error responses, expose measured capabilities after inference and bound identifier displays. |
| Medium | telemetry / economics / reports | Sample timestamps and missing readings lack enough context. Cost output can omit binding assumptions and use a latency-unqualified stage for provisioning estimates. | Record sample coverage and board scope, separate provisioned billing from planning assumptions and clearly label unavailable capacity. |
| Medium | runner / workload | Short run deadlines, process sleep and hard stops can leave held admissions and unreached arrivals indistinguishable. Configuration is hashed, but current evidence lacks tool version and portable resume semantics. | Preserve bounded interruption evidence, record planned and reached counts, pin resume to the current evidence format and preserve separate attempts. |
| Low | validation | Five repository-wide Ruff errors in historical reproduction scripts. | Keep original results and make mechanical script corrections or explicitly gate the historical scripts separately. |

The high-severity defects were addressed in the release candidate and verified with targeted network, evidence and protocol tests. The release record identifies the Windows and WSL checks, two real CUDA launches, independent recounts, and remaining staging conditions. Older bundles remain readable under their original schema and their reanalysis carries separate caveats.
